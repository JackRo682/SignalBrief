# SignalBrief 채용 포트폴리오 콘텐츠 초안

대상: 주니어 핀테크·AI Product Manager 채용. 작성 기준: 2026-10-10. 슬라이드 콘텐츠 초안이며 실제 참여자 성과나 A/C 모델 실험 성과를 주장하지 않는다.

## 1. 금융 AI의 숫자와 근거를 함께 검증하는 제품

SignalBrief는 공시의 변화를 읽고 원문 근거를 확인하는 제품이다. 이번 작업에서는 검증 가능한 범위를 매출·영업이익으로 한정하고, 실험 데이터와 실패 기록을 남겼다.

증거: [저장소](https://github.com/JackRo682/SignalBrief), [기존 수정 PR #13](https://github.com/JackRo682/SignalBrief/pull/13). 역할 설명: 문제 정의, 검증 기준 설계, 구현 우선순위 설정, QA와 출시 판단. 코드는 AI 에이전트와 함께 작성했다. 독립 인간 검수·실제 고객 조사까지 수행했다고 표현하지 않는다.

## 2. 매출 제목 아래 다른 수치가 나타난 문제

카드가 첫 번째 사실을 근거로 선택하면서 매출 제목 아래 영업이익이나 과거 기간이 표시될 수 있었다. 원문의 숫자가 맞아도 제목을 지지하는 근거는 틀릴 수 있다.

화면 구성 제안: 제목·선택한 지표·원문 기간을 나란히 표시한 사례 도식. 실제 운영 전후 화면이 없으므로 이를 운영 스크린샷으로 표현하지 않는다. 근거: `docs/FINAL_TECHNICAL_VALIDATION_20261009.md`, `tests/test_card_evidence.py`.

## 3. 수치·기간·출처를 별도 합격 기준으로 정의

합격 기준은 같은 지표, 현재 사실 ID, 동일 비교 방식, 정확한 단위와 기간, 원문 출처의 일치다. 오래됐거나 모호한 근거는 표시하지 않는다. 승인 버튼도 검증 실패를 우회할 수 없다.

근거: Python/Edge 근거 선택 코드와 회귀 테스트. 출시 완료와 코드 검증을 구분한다. 운영 API 배포는 이번 작업에 포함하지 않았다.

## 4. Apple 공시로 오류를 재현하고 확인

기존 사례는 2026년 3월 28일 종료 분기와 6월 27일 종료 분기를 비교한다. 매출은 USD million 기준 111,184에서 109,417로 변했고 전분기 대비 −1.5893%다. 영업이익은 35,885에서 35,695로 변했고 −0.5295%다. 6개월과 9개월 누적액을 분기 성장률로 비교하지 않는다.

원문: [0000320193-26-000013](https://www.sec.gov/Archives/edgar/data/320193/000032019326000013/aapl-20260328.htm), [0000320193-26-000020](https://www.sec.gov/Archives/edgar/data/320193/000032019326000020/aapl-20260627.htm). 2개 문서의 16개 값은 자동 원문 재검증을 통과했다. 별도 인간 수치 검수는 미완료다.

## 5. 30개 공시 비교 쌍과 48개 원문 보존

개발 데이터는 AAPL 4쌍, MSFT 3쌍, NVDA 3쌍이다. 보류 평가 데이터는 AAPL 7쌍, MSFT 7쌍, NVDA 6쌍이다. 이번 벤치마크의 비교 방식은 전년 동기 분기다. 기존 전분기 사례와 혼용하지 않는다.

접수번호, 공식 URL, 공시일, 회계기간, 원본 SHA-256을 저장한다. 분리된 데이터 사이에 동일 접수번호·동일 원문은 없다. 근거: `evals/financial-v1/manifest.json`, `manifest.sha256`.

## 6. A·B·C를 같은 조건에서 비교하는 평가 설계

A는 원문 직접 LLM 요약이다. B는 구조 추출과 Decimal 계산이다. C는 B에 AI 해석과 근거 검증을 더한다. 공통 범위는 연결 매출·영업이익의 분기 값 4개와 변화 2개다.

모델·프롬프트·원본·출력 제한·실패·사용량을 기록한다. A/C는 예산 승인 전 실행하지 않았다. C의 해석 검증은 산술 문장으로 제한한다. 포괄적인 의미 검증 능력으로 소개하지 않는다. 근거: `scripts/run_financial_benchmark.py`, 두 benchmark 프롬프트.

## 7. 개발 실험은 10쌍 중 4쌍 완료

B의 유용한 완료율은 4/10, 40%다. 전체 요구값 기준으로 수치와 인용의 자동 후보 일치율은 각각 16/40이다. 반환한 값만 보면 16/16이지만, 이를 전체 제품 정확도 100%로 표현하지 않는다. 비교 계산은 요구 20개 중 8개를 반환했고 8개 모두 자동 후보와 일치했다.

6쌍은 명시적으로 중단했다. MSFT 3쌍은 문서 크기 제한, NVDA 3쌍은 표 머리글·XBRL 기간 검증 실패다. 4개 완료 쌍은 모두 AAPL이므로 다른 기업으로 일반화할 수 없다. 근거: `verification/financial-20261010/development-B-final.json`.

## 8. 비용과 속도는 측정 범위를 함께 공개

로컬 오프라인 B 처리 시간의 중앙값은 약 538ms, p95는 약 927ms다. 10개 시도 전체를 포함하며 다운로드와 독립 후보값 생성 시간은 제외했다. 운영 사용자 응답 시간은 측정하지 않았다.

신규 유료 AI 요청은 0회다. B의 API 비용은 $0이며 A/C의 실제 비용·지연시간은 미측정이다. 토큰 단가 추정과 청구서 실비를 분리한다. 과거 Apple 비용 추정을 이번 3개 방법 비교 결과로 사용하지 않는다.

## 9. 잘못된 입력과 권한 공격을 먼저 검사

실제 원문 기반 주장 변조 24개와 시스템 오류·권한 사례 16개를 실행했다. 40/40이 통과했다. 범위는 잘못된 값·단위·기간·출처, 누락 공시, 타임아웃·429, 중복 처리, 사용자 간 접근, 관리자 권한 상승과 근거 없는 발행이다.

최종 로컬 백엔드는 332개 통과, PostgreSQL 관련 37개 제외였다. 별도 폐기용 PostgreSQL 실행에서는 기본·호스팅 검사 2개와 워크스페이스 격리 검사 35개가 통과했다. 40개 공격 사례는 백엔드 테스트에 포함된 부분집합이다. 테스트용 응답과 합성 사용자를 사용한 소프트웨어 검증이며 실제 AI나 사용자 실험 결과가 아니다. 근거: `adversarial.json`, `adversarial.xml`, `backend-delivery.xml`, `workspace.xml`.

## 10. 통과한 검사와 남은 출시 위험

운영 읽기 전용 검사 8개, Python 의존성 감사와 운영 npm 의존성 감사는 통과했다. 전체 npm 감사에는 개발 도구의 high 취약점 5개가 남았다. Windows 웹 빌드·브라우저 실행은 환경 권한 오류로 막혔다. 새 브랜치 Linux CI 결과는 별도 기록으로 확인한다.

실제 두 계정의 로그인·격리, 인간 수치 검수, 취약점 처리 또는 책임자의 위험 수용, 출시 승인이 남았다. 판단은 병합·운영 배포 BLOCKED다. 기술적으로 병합 가능하다는 GitHub 표시를 출시 승인으로 해석하지 않는다.

## 11. 사용성 실험은 실제 참여자 모집 전

질문은 근거가 연결된 화면이 수치·비교 기간 확인을 돕는지다. 6~8명을 대상으로 서로 다른 공시 과제 두 개와 AB/BA 순서를 사용한다. 주요 지표는 방향·기간 정답률이고, 시간·근거 열람·확신 수준을 함께 기록한다.

동의 후 익명 이벤트만 브라우저 메모리에 기록하는 로컬 도구를 구현했다. 철회하면 기록을 지운다. 실제 A/C 출력과 독립 검수를 확보한 뒤 진행한다. 참여자 0명, 성과 미측정이다. 근거: `docs/USABILITY_EXPERIMENT.md`, `tools/usability-study.html`. 자동 UI 테스트 화면을 인간 참여자 화면으로 소개하지 않는다.

## 12. 다음 의사결정은 범위 확장보다 검증 완료

우선순위는 독립 검수, 격리된 실제 계정 검사, 개발 의존성 위험 처리, MSFT/NVDA 파서 지원, 승인된 A/C 실험이다. 이후 코드·프롬프트를 고정하고 보류 20쌍을 한 번 평가한다. 결과를 본 뒤 수정하면 새 보류 데이터가 필요하다.

이번 산출물은 재현 가능한 원문·실험 코드·실제 실패 기록·출시 판단이다. 아직 입증하지 않은 모델 우월성, 인간 검수 정확도, 사용자 만족도나 사업 성과를 포트폴리오에 추가하지 않는다. 검토용 신규 PR과 최종 CI 링크는 `verification/financial-20261010/remote-status.json`에서 확인한다.
