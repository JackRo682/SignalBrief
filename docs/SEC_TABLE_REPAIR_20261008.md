# SEC 표·Inline XBRL 수정 및 검증

**Apple 1쌍의 선언된 매출·영업이익 분석 및 발행 흐름: PASS. 전체 재무제표·실서비스 완료 판정: FAIL.** 2026-10-09 KST 기준 실제 AI 2회, 16/16 수치 검증, 운영 DB·Storage 원본 해시 재검증, 공시 간 분기 비교, 두 이벤트 승인·감사 기록, 모바일 Today 90일 조회 표시까지 확인했다. 다만 전체 지표 지원과 별도 일반 사용자 두 계정의 운영 브라우저 권한 검증은 완료하지 않았다. 기존 DB·Storage·API 키 연결을 재사용했다. 운영 배포·main 병합은 하지 않았다.

## 재현한 원인과 수정

기존 `normalized_text()`는 숨겨진 XBRL 자원과 표 셀 병합 구조를 제거했다. `validate_fact()`는 연속 인용문 하나에 지표·값·단위·기간·연결 범위가 있어야 하고 `bound_numeric_claim()`은 하나의 금액만 허용한다. 따라서 실제 Apple의 `Total net sales` 행은 숫자가 맞아도 별도 머리글의 단위와 기간을 증명하지 못한다. 이 실제 행이 기존 검증기에서 부분 지원으로 거부되는 회귀 테스트를 남겼다. 기존 모델의 89개 후보는 원래 저장되지 않아 과거 후보별 정확한 재실행은 불가능하다. 집계된 실패 사유와 원본 표 구조를 근거로 원인을 재현했다.

| 기존 문제 | 수정 |
|---|---|
| 원문과 다른 연속 인용 | 표의 원문 조각을 좌표와 함께 명시적으로 재구성. 연속 인용이라고 표시하지 않음 |
| 지표 누락 | 같은 행의 표시 이름과 허용된 US GAAP concept를 함께 대조 |
| 통화·단위 누락 | HTML의 `$`와 단위 설명, XBRL unit의 ISO4217 USD 및 scale 교차 확인 |
| 기간 누락 | 해당 열의 날짜/개월 수와 context의 시작일·종료일을 대조 |
| 다중 열 오류 | rowspan/colspan을 논리 격자로 확장하여 다중 행 머리글 연결 |
| 근거 일부만 지원 | 원본 바이트·해시·셀·context/unit를 다시 계산해 후보의 모든 필드 일치 요구. 누락·중복·변조는 차단 |

`sec-tables-v1`은 명시적으로 선택하는 파일럿 경로다. **현재 범위는 연결 손익계산서의 매출·영업이익**이다. Apple 원문의 756개 Inline XBRL 숫자 중 8개를 검증했고 748개는 범위 밖으로 별도 기록했다. 이를 전체 공시 분석 성공으로 표시하지 않는다. 기존 전체 문서 경로와 검증 규칙은 유지했다. 배당·CAPEX·주석·부문별 지표, 임의 taxonomy/통화/변환 형식, XBRL 없는 표까지 지원한다고 주장하지 않는다. 확인할 수 없는 형식은 실패한다.

원본 gzip/base64를 별도 parser version의 DB 청크에 보존하여 원문 저장소와 같은 SHA-256에 묶는다. 외부 모델은 필요한 셀과 머리글만 받는다. 원문 압축 해제는 4MB로 제한한다. 서버 승인 시 원문을 재파싱하고 필드·인용·범위의 완전성을 다시 검사한다. 기존 hosted SQL의 인용문 포함 조건도 충족하며 해당 SQL 조건은 바꾸지 않았다. 표시 인용에 원문 조각의 재구성임을 명시한다. 모델 후보는 실패한 후보까지 AI 실행 이력에 저장해 다음 오류를 재현할 수 있게 했다.

기간은 fiscal quarter를 calendar quarter로 임의 변환하지 않고 `시작일/종료일`로 저장한다. Decimal 증감 계산을 유지하고 6개월/9개월 누적을 분기 대비로 비교하지 않는다. 최신 문서 안의 비교 우선순위는 동일 기간 수정 → 인접 분기 → 전년 동기이며, 과거 비교 열이 현재 브리핑의 대표 변화가 되지 않도록 현재 종료 기간을 선택한다.

## 테스트와 미검증 구분

파서·변조·기간 비교 및 실제 두 원본의 쌍 비교 테스트 24건, 실제 SEC 바이트와 격리된 SQLite/API를 사용하는 파이프라인 테스트 4건을 추가했다. 28건 모두 통과했다. 후자의 모델 응답은 테스트 대역이며 실제 AI 성공률이 아니다. 로컬 API에서 관리자 승인 후 180일 범위 피드 노출, 반려 후 비노출, 일반 사용자 승인 거부, 감사 기록, 재처리 시 단일 이벤트·실행 유지, 잘못된 값/누락의 승인 거부를 확인했다.

구현 커밋 `061efb13`의 기존 포함 로컬 백엔드 회귀: 294 passed / 37 skipped. Ruff·컴파일·OpenAPI·웹 lint/typecheck 통과. 로컬 웹 단위/빌드는 Windows native path EPERM으로 실패했다. 동일 커밋 Linux [전체 검증](https://github.com/JackRo682/SignalBrief/actions/runs/37782420740)은 성공했고 브라우저 76 passed / 16 skipped를 확인했다. 기본 PostgreSQL job은 1 passed / 36 skipped이므로 이것만으로 전체 DB 검증을 통과했다고 하지 않는다. 별도 폐기용 [workspace 보안 재현](https://github.com/JackRo682/SignalBrief/actions/runs/37782420715)은 35 passed, [hosted schema 재현](https://github.com/JackRo682/SignalBrief/actions/runs/37782420806)은 2 passed였다. 마지막 쌍 회귀 테스트 추가 후 전체 백엔드는 295 passed / 37 skipped이며 `checks.json`에 기록했다.

실제 환경 검증: 두 이벤트 `b7818c3d-0614-5411-a4f7-2227baebd5a4`, `12877d3d-ef23-5765-88b7-2754de0e95af` 모두 published, 각 8개 supported. 운영 UI 승인과 audit approve 각 1건을 확인했다. 2026-10-08 13:21:39 UTC / 19:29:11 UTC에 발행됐다. private Storage 원본을 다시 내려받아 DB 해시와 대조하고 Python 근거 검증기를 재실행해 모두 통과했다. 승인 후 analyze를 재실행해도 2개 이벤트·2개 실행·16개 사실과 비용이 유지됐다. 기존 실패 이벤트 `65ca674b-bf8d-5947-9ce6-bdeacefcaee0`는 rejected이며 운영 공개 가시성 함수가 false였다.

Today는 기존 모바일 화면에서 **전체 보기 → 최근 90일**로 설정해 두 번째 이벤트와 `매출 감소 -1.5893%`를 실제 확인했다. 기본 데스크톱 30일에서는 두 공시 모두 기간 밖이므로 표시되지 않는다. 5월 공시는 모바일 최대 90일 밖이며 API 180일 확인과 구분한다. 표시를 위해 공시 날짜를 조작하지 않았다. Today 카드의 짧은 근거 미리보기에는 같은 이벤트의 영업이익 인용이 먼저 나올 수 있어 매출 제목과의 정렬은 후속 UI 개선 항목이다. 전체 근거·수치는 저장된 이벤트에서 확인 가능하다.

기존 운영 계정의 로그아웃 → 로그인 화면 이동, 로그아웃 상태에서 `/ops` 접근 → 로그인 화면 이동, Google 재로그인 → Today 복귀를 이번 실행에서 실제 확인했다.

미검증/제한: 일반 사용자 두 계정의 운영 브라우저 권한·사용자 간 격리, 두 번째 8개 값의 별도 인간 검수, 범위 밖 재무 지표와 일반 XBRL 형식. 권한 거부·사용자 격리는 안전한 격리 테스트에서 확인한 범위만 인정한다. 운영 DB에서 파괴적인 테스트는 하지 않았다. 전체 재무제표 분석 또는 모든 완료 조건 충족으로 표시하지 않는다.

## 실제 사용량과 비용

사용자의 계속 사용 승인 후 새 경로로 **2회** 호출했다. 모델은 `gpt-4.1-mini-2025-04-14`. 첫 호출 입력 4,209 / 출력 1,836 / 0.0046212 USD, 두 번째 입력 4,207 / 출력 1,820 / 0.0045948 USD. 합계 **입력 8,416 / 출력 3,656 / 0.009216 USD**. API 응답의 실제 토큰 수에 기존 설정 단가 입력/출력 100만 토큰당 0.4/1.6 USD를 적용한 추정 비용이며 결제 명세서의 확정 청구액은 아니다. 이전 실패 실행 0.036076 USD를 포함한 기록된 비용은 0.045292 USD다. 누적 예약 장부와 기존 100 USD 상한은 초기화하거나 변경하지 않았다.

첫 공시가 실제 검증을 통과하고 승인된 후 두 번째를 처리했다. 승인 후 재처리는 신규 API 호출 없이 끝났다. 10쌍 처리는 실행하지 않았다. CLI의 최종 `NEEDS_REVIEW`는 별도 서비스 검증을 요구하는 보수적 표식이므로 이를 전체 PASS로 덮어쓰지 않았다. 단계별 실증 결과는 `verification/sec-tables-20261008/live.json`과 본 문서에서 구분한다.

```sh
python scripts/check_sec_table_pilot.py  # 네트워크·키·유료 호출 없는 재현
# 사용자 승인으로 실행한 경로. 이미 처리된 동일 revision은 재사용한다.
python -m signalbrief.live_trial analyze --directory var/live-trial/pilot-xsl-complete --revision sec-tables-v1
```

## 10쌍 확대 계획 — 실행하지 않음

첫 1쌍의 정확한 수치·두 출처 비교·인간 검수·승인·Today 및 권한 검증이 모두 통과해야 한다. 그 후 별도 사용자 승인을 받아 Apple 4쌍, Microsoft 3쌍, NVIDIA 3쌍으로 확대한다. 각 쌍의 원본 해시, concept/context/unit/scale, 셀 위치, 기간 종류, 증감, 승인/반려·감사·노출 결과, 토큰/비용을 저장한다. 연간/정정 공시는 별도로 분류하고 누적 기간이 다른 값은 비교 불가로 남긴다. 어느 단계든 실패하면 사유를 기록하고 해당 쌍의 발행을 차단한다. 현재 10쌍은 시작하지 않았다.

기술 참고: [Inline XBRL 1.1](https://specifications.xbrl.org/work-product-index-inline-xbrl-inline-xbrl-1.1.html), [Transformation Registry 5](https://specifications.xbrl.org/work-product-index-inline-xbrl-transformation-registry-5.html). 일반 XBRL 처리기 전체를 구현한 것은 아니다.
