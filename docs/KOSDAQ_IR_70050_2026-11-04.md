## Interpretation and limits

Only the exact three-row `1. 일시` matrix supplies the event date: event-day and local-time headings, explicit start/end headings, then two complete ISO dates and local clocks. Decision dates and IR-material publication dates are excluded. The complete remaining field set is required. A range is one event at its declared start, with the end retained in evidence and both dates included in a Korean “period start” title. Ranges over 31 days, reversed dates, incomplete matrices, and ambiguous corrections fail closed.

The source labels clocks as local time. The calendar therefore remains date-only with `timezone: null`; venue location does not manufacture a timezone. A correction must have a separately verified correction table, original filing date, explicit family, and selected current event matrix. Cancellation/withdrawal markers are rejected. Original receipts remain stable event identities.

The additive SQL migration binds `70050` entry locations to a `70050` document in a v2 family and a canonical KOSDAQ source. It validates quoted start/end dates, range title and optional end, while retaining all archive, company, family, stale-replay, and privilege gates. Missing or null range ends explicitly return false.

## Verification

- 71 focused TypeScript tests passed: the existing 58 99664 cases plus 13 KOSDAQ cases.
- An offline replay decoded the original raw bytes, checked all ten SHA-256 hashes, and parsed all five actual main/body pairs successfully, including the multi-day event and original/correction family.
- The 25 native PostgreSQL regressions are included explicitly in `official-calendar-verification`. They cover valid publication, malformed ranges, missing/null ends, source/template binding, correction identity, archive completeness, privileges, and legacy ingestion. They collect cleanly locally; native execution requires the disposable PostgreSQL CI service.
- An independent review found and verified the fix for a missing-end SQL NULL guard, then reported no further runtime or SQL blocker.
